MethScope

cliv0.1.1 ↗

Ultra-fast analysis of sparse DNA methylomes via MRMP (Most Recurrent Methylation Pattern) encoding — cell-type annotation, deconvolution, and genome-wide CpG upscaling, as a single pure-C binary. No R, no Python at runtime.

GitHub· models· YAME· R / MethScope· hg38 · mm10 · WGBS · single-cell · spatial

Install — the binary, and what it can fetch

Every model is one self-contained bundle carrying its own MRMP feature definition (and labels), so a query .cg runs directly — no separate annotation files. fetch carries the catalog of models and the example .cg fixtures; each workflow below opens by fetching just what it needs. It never prompts, so it is safe inside a container build.

# conda — installs the `methscope` binary
conda install -c zhou-lab -c conda-forge methscope

# to run the examples and the analysis around them, add the two
# tools they pipe through: yame reads and slices .cg, tabl aligns TSV
conda install -c zhou-lab -c conda-forge yame tabl

# or build from source (bundles YAME)
git clone --recurse-submodules https://github.com/zhou-lab/methscope-cli
cd methscope-cli && make

# what is available, and what is already local
methscope fetch
store   ~/.cache/methscope

Downloads land on a .part sibling and are renamed only once the byte count matches the catalog, so an interrupted fetch can never leave a short file that later reads as a valid model. Have yame on PATH and the conda env that provided libxgboost active.

Build MRMP — the feature foundation

An MRMP is one recurrent methylation pattern across a reference panel; the mask that labels every genomic CpG with its pattern is what every model is built on. mrmp-build constructs it natively from a discretized reference .cg — no YAME + awk + sort pipeline, ~576 MB peak, ~50 s for a whole-genome reference. The fetchable example below is chr20 only, so it finishes in about a second.

# work in a scratch dir and fetch into it, so inputs and outputs
# sit together (the store is $METHSCOPE_DATA_DIR, else ~/.cache/methscope)
mkdir -p ~/tmp/methscope && cd ~/tmp/methscope
export METHSCOPE_DATA_DIR="."

# a 40-cell-type chr20 reference, small enough to fetch (39.5 MB)
methscope fetch human_hg38_40_celltypes_chr20.cg

methscope mrmp-build human_hg38_40_celltypes_chr20.cg chr20_40celltypes.mrmp

Ranking is deterministic (count desc, key asc), so a build is byte-reproducible from the reference alone — hover the .mrmp for the on-disk scheme. The artifact is the build pipeline's currency: upscale-featurize, upscale-set-units, and upscale-train all read it, so the sidecar's group map and the mask a model ships cannot drift apart.

Classify — cell type, sex, any label

Classify a methylome against a bundled classifier. Fetching is idempotent and prints the path it guarantees, so $(methscope fetch NAME) is usable directly as an argument — the block below runs as-is on a clean machine.

MSBNDL1 — a classifier bundle (.ubjx)

One self-describing file: the inner model, its MRMP feature definition, and the labels. A query .cg therefore runs directly — no separate annotation files to match up. Three frameworks are supported (xgboost / logistic / threshold) and the kind section records which, so classify needs no flag to know how to run it.

labels  62 cell types (linear models also store per-feature means)

Train — fit your own classifier

# work in a scratch dir and fetch into it, so inputs and outputs
# sit together (the store is $METHSCOPE_DATA_DIR, else ~/.cache/methscope)
mkdir -p ~/tmp/methscope && cd ~/tmp/methscope
export METHSCOPE_DATA_DIR="."

# the 40-cell-type chr20 reference doubles as training data:
# label each cell by lineage, straight from the sample names
methscope fetch human_hg38_40_celltypes_chr20.cg
methscope mrmp-build human_hg38_40_celltypes_chr20.cg chr20.mrmp
methscope mrmp-export --top 1000 chr20.mrmp chr20.cm
cut -f1 human_hg38_40_celltypes_chr20.cg.idx | sed 's/^GSM[0-9]*_//; s/-Z[0-9A-Z]*$//' | sed -E 's/.*Endothel.*|.*Endothelium.*/Endothelial/; s/.*Epithelial.*|.*Keratinocytes.*|.*Podocytes.*/Epithelial/; s/^Blood-.*|.*Macrophages.*/Immune/; s/.*Smooth-Muscle.*|Skeletal-Muscle|.*Cardiomyocyte.*/Muscle/; s/^Neuron$|.*Oligodendrocytes.*/Neural/; s/.*Fibroblasts.*|Adipocytes|Lung-Pleura/Mesenchymal/; s/^(Liver-Hepatocytes|Pancreas-Acinar|Pancreas-Beta)$/Secretory/' > labels.txt

# features + labels -> one runnable bundle, in a single step
# (the positional takes the runtime .cm, not the .mrmp artifact)
methscope classify-train -l labels.txt -o chr20_lineage.ubjx human_hg38_40_celltypes_chr20.cg chr20.cm

Linear models store per-feature training means, so missing/sparse betas are imputed at classify time — accurate even at <1% genome coverage.

Deconvolve — cell-type proportions

Solve a mixture against a signature panel by non-negative least squares. Uses all MRMP patterns and is robust to extreme sparsity, so it works on cfDNA-scale coverage.

Upscale / impute — the whole-genome decoder

Impute dense CpG methylation from a sparse methylome with a bundled decoder — pure-C inference, no CUDA or BLAS at run time. Output is a .cg of binary 0/1 calls; --probs emits per-CpG probabilities instead. Training that decoder is a separate, three-step pipeline, and every step reads the same .mrmp.

Impute — with a shipped decoder

Training runs on CPU by default and threads over units, which are independent — that is what makes the run resumable. The 109 chr20 units take ~17 s on 8 threads. make CUDA=1 CUDA_HOME=/path/to/cuda CUDA_ARCH=sm_80 builds the GPU backend, which is picked automatically when a device answers; checkpoints are interchangeable, so you can start on CPU and finish on a GPU node.

MethScope — Ultra-fast Analysis of Sparse DNA Methylome via Recurrent Pattern Encoding. Built on YAME. AGPL-3.0-or-later · github.com/zhou-lab/methscope-cli
methscope bundle 
Usage:
  methscope bundle -m <ref.mrmp> -o <out> <model>

Purpose:
  Bundle a model with the MRMP definition it needs into one self-contained
  file, so a query .cg can be featurized + run without a separate .mrmp.
  Works for any model; by convention give the output an 'x' suffix:
    booster.ubj  -> booster.ubjx   (predict)
    model.updec  -> model.updecx   (upscale)

Options:
  -m <ref.mrmp>   the MRMP definition (a YAME .cm) to bundle (required).
  -k <kind>       framework mark to record (xgboost/threshold/logistic); required
                  for a classifier .ubjx that `predict` will run (predict rejects
                  an unmarked bundle). Also used to re-stamp an existing model.
  -l <meta.tsv>   embed class labels (a 'labels<TAB>l1,l2,...' line) into the
                  booster before bundling — for a raw (e.g. R-exported) .ubj.
  -O <outcpg.cm>  output-CpG locations (upscale only): a YAME mask marking the
                  CpGs the model imputes. With it, `upscale` writes a full-genome
                  .cg; without it, a dense block .cg.
  -o <out>        output bundle path (required).
  -h              Show this help message.
 methscope classify 
Usage:
  methscope classify [options] <query.cg> <model.ubjx>
  methscope classify [options] <query.cg> <ref.mrmp> <booster.ubj>

Purpose:
  Predict a label (cell type, sex, ... — whatever the model was trained on)
  and a confidence score for each query record, by featurizing the query
  against the MRMP reference and running the booster.

Arguments:
  <query.cg>     Query methylome(s); '-' reads a .cg stream from stdin
                 (cells are then named 1,2,3,... as a stream has no index).
  <model.ubjx>   A self-contained bundle of the booster + its MRMP (from
                 `train -o model.ubjx` or `bundle`) — the recommended
                 single-file form.
  <ref.mrmp>     MRMP pattern definition (a YAME .cm) to featurize the query
                 (loose form). A bundle (.ubjx/.updecx) also works here.
  <booster.ubj>  Loose booster with class labels embedded (see train / bundle -l).

Options:
  -o <out.tsv>   Write output to a file instead of stdout.
  --probs        Append one column per class with its predicted probability.
  --no-header    Suppress the header line.
  -h             Show this help message.

Output columns:
  cell  prediction_label  confidence  [<class1> <class2> ... with --probs]
 methscope classify-train 
Usage:
  methscope classify-train -l <labels.txt> -o <out.ubjx> [options] <query.cg> <ref.cm>

Purpose:
  Train a multiclass classifier for any per-record label (cell type, sex,
  ...; fixed hyperparameters, no grid search) and write a self-describing
  model with the class labels embedded.

Arguments:
  <query.cg>   Training methylome(s), one record per sample.
  <ref.cm>     MRMP pattern definition, the runtime .cm from mrmp-export.
               A bundle (.ubjx/.updecx) also works; its MRMP is used.
               Features are the MRMP states; the 'Pna' NA-background state is
               excluded by default (see --include-pna).

Options:
  -l <labels.txt>  One label per query record, in query order (required).
  -o <out.ubjx>    Output model path (required). A '.ubjx' name writes a
                   self-contained bundle (booster + MRMP) that `predict` can
                   run directly; a plain '.ubj' writes just the loose booster.
                   The bundled MRMP is TRIMMED to exactly the patterns used
                   (others folded into 'Pna'), and `predict` uses that same set.
  -p <npattern>    Use the first N patterns by RECURRENCE RANK. Only meaningful
                   when patterns are named P1,P2,... (auto MRMPs); for curated
                   named markers (e.g. Xa_hi/Xa_lo) leave it unset. Default:
                   all non-'Pna' states.
  --include-pna    Also use the 'Pna' NA-background state as a feature
                   (default: excluded).
  --framework <f>  Model framework (default: xgboost):
                     xgboost    gradient-boosted trees (multiclass).
                     threshold  interpretable binary linear rule; per-feature
                                weight = class-mean difference, decision at the
                                midpoint of the two class score-centroids.
                     logistic   binary L2-regularized logistic regression.
                   threshold/logistic are binary-only and require a .ubjx output.
  -n <nrounds>     Boosting rounds, xgboost only (default: round(sqrt(n_cells))).
  -h               Show this help message.
 methscope deconv 
Usage:
  methscope deconv [options] <mixture.cg> <panel.refx>

Purpose:
  Estimate per-cell cell-type proportions by non-negative least squares
  (NNLS) deconvolution against a cell-type signature reference.

Arguments:
  <mixture.cg>     Mixture methylome(s); '-' reads a .cg stream from stdin
                   (cells are then named 1,2,3,... as a stream has no index).
  <panel.refx>     A self-contained reference bundle (signature + MRMP) from
                   `matrix --refx`. '-' reads the .refx from stdin, so you can
                   build + deconvolve in one pipe:
                     matrix --refx -o - pseudobulk.cg ref.mrmp \
                       | deconv mixture.cg -

Options:
  -o <out.tsv>     Write output to a file instead of stdout.
  --min-cov <k>    Per cell, only use patterns with >= k covered CpGs in the
                   mixture (default: 1). Higher k (e.g. 3) drops thinly-
                   covered, noisy patterns -- helps on sparse input.
  --no-header      Suppress the header line.
  -h               Show this help message.

Output:
  One row per mixture cell; columns are cell types (proportions summing to 1).
 methscope deconv-build-ref 
Usage:
  methscope deconv-build-ref [options] -o <out.refx> <celltypes.cg> <ref.mrmp>

Purpose:
  Build a .refx deconvolution reference: summarize each cell type against the

 methscope upscale 
Usage:
  methscope upscale [options] <model.updec|.updecx> [input]

Purpose:
  Impute CpG methylation from a sparse methylome. Unified UPDEC2 models
  predict the whole genome; legacy UPDEC1 block models remain readable.
  Both inference paths are pure C and require neither CUDA nor BLAS.

Arguments:
  <model>   A bare decoder (.updec/.updec2) OR a bundle with the MRMP attached
            (.updecx, from `bundle`). The form selects the input below.
  [input]   For .updec : a feature TSV (one row per sample, n_in numeric cols).
            For .updecx: a query .cg, featurized internally against the bundled
            MRMP. '-' or omitted reads from stdin; for .updec a header row is
            auto-detected and empty/NA fields are imputed with the model means.

Options:
  -o <out>   Write output to a file instead of stdout (.cg is binary -- use -o).
  --probs    Emit per-CpG probabilities as TSV instead of a .cg of 0/1 calls.
  -h         Show this help message.

Output:
  A YAME .cg (format 6), one record per input sample. UPDEC2 output is always
  in whole-genome CpG order. For legacy UPDEC1, if the bundle carries an
  outcpg.cm (the imputed-CpG locations), the .cg spans the whole genome with the
  block's CpGs called (no NA) and the rest NA; otherwise a dense block of n_out
  CpGs. With --probs, a TSV of per-CpG probabilities (one row per sample).
