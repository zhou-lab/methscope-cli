MethScope

cliv0.1.1 ↗

Ultra-fast analysis of sparse DNA methylomes via MRMP (Most Recurrent Methylation Pattern) encoding — cell-type annotation, deconvolution, and genome-wide CpG upscaling, as a single pure-C binary. No R, no Python at runtime.

GitHub· models· YAME· R / MethScope· hg38 · mm10 · WGBS · single-cell · spatial

Install & fetch the models

# conda — installs the `methscope` binary
conda install -c zhou-lab \
  -c conda-forge methscope

# or build from source (bundles YAME)
git clone --recurse-submodules \
  https://github.com/zhou-lab/methscope-cli
cd methscope-cli && make

# pretrained models — no hf client needed
methscope fetch all

# test fixtures + catalog — from GitHub
git clone \
  https://github.com/zhou-lab/methscope_data

Every model is one self-contained bundle that already carries its MRMP feature definition (and labels), so a query .cg runs directly — no separate annotation files. Examples below use models/ (from HuggingFace) and test/ (from the methscope_data checkout).

fetch — pretrained models

The models are too large for git, so they live on HuggingFace and fetch carries the catalog. With no name it lists what exists and what is already local. It never prompts, so it is safe in a container build.

methscope fetch

hg38_65celltypes   27.6 MB    deconvolution (NNLS)           refx         -
hg38_10k1          27.7 MB    CpG upscaling (one block)      UPDEC1       -
hg38_wg            2.8 GB     CpG upscaling (whole genome)   UPDEC2       -

6 models, 2.9 GB total; 30.2 KB present

methscope fetch hg38_celltype,hg38_sex   # or: all
# --store DIR overrides $METHSCOPE_HOME (default ~/.methscope/models)

Downloads land on a .part sibling and are renamed only once the byte count matches the catalog, so an interrupted fetch can never leave a short file that later reads as a valid model.

mrmp-build / mrmp-export — the MRMP foundation

An MRMP is one recurrent methylation pattern across a reference panel; the mask that labels every genomic CpG with its pattern is what every model is built on. mrmp-build constructs it natively from a discretized reference .cg — no YAME + awk + sort pipeline, ~576 MB peak.

methscope mrmp-build ref.cg panel.mrmp
methscope inspect panel.mrmp --patterns
# runtime mask — inspection only, not a pipeline step
methscope mrmp-export --top 1000 \
  panel.mrmp panel.cm
MRMPIDX1 — every candidate ranked, no top-K baked in

             11111111111111111111111111111111111  10,736,116  P1

Ranking is deterministic (count desc, key asc), so a build is byte-reproducible from the reference alone — hover panel.mrmp above for the on-disk scheme. The artifact is the build pipeline's currency — upscale-featurize, upscale-set-units, and upscale-train all read it, so the sidecar's group map and the mask a model ships cannot drift apart. The .cm is the runtime form, materialized into the bundle at train time; export --mask is for inspection, not a pipeline step.

classify-train … classify — cell type / sex

Fit a label classifier over MRMP features and bundle it with its MRMP + labels in one step, then classify with it. Three frameworks (xgboost / logistic / threshold); the bundle records which.

# fit + bundle in one step
methscope classify-train -l labels.txt \
  -o hg38_celltype.ubjx query.cg panel.mrmp
# --framework xgboost | logistic | threshold

# 4 Loyfer cells vs the Zhou2025 62-type atlas
methscope classify cells.cg models/hg38_celltype.ubjx
cell             prediction_label  confidence
Oligodendrocyte  ODC               0.9151
Pancreas-Beta    Beta              0.9307
Blood-NK         NK CD16           0.8127
# Loyfer truth -> Zhou label: 4/4 concordant.
# same call runs a sex / age / any bundled model

Linear models store per-feature training means, so missing/sparse betas are imputed at predict time — accurate even at <1% genome coverage.

deconv-build-ref … deconv — cell-type proportions

Summarize per-cell-type pseudobulks against the MRMP into a self-contained .refx, then solve a mixture against it by non-negative least squares → a proportion per cell type. Uses all MRMP patterns; robust to extreme sparsity.

# 1. build the signature panel
methscope deconv-build-ref -o panel.refx \
  celltypes.cg panel.mrmp
# --matrix emits the raw record x pattern beta TSV instead

# 2. deconvolve a mixture against it
methscope deconv test/human_hg38_immune_mixture.cg \
  models/hg38_65celltypes.refx
cell  … Macrophage  Mono    NK_CD56  …
1     … 0.7486      0.2370  0.0000   …

The 65-type reference spans 58 Zhou single-cell + 7 Loyfer organ/blood types for whole-body / cfDNA deconvolution.

upscale-train … upscale — the whole-genome decoder

Train the unified upscale model (UPDEC2) on CUDA — one processing unit per MRMP membership — then impute with it in pure C, no CUDA or BLAS at run time. The three build steps all read the same .mrmp.

# 1. featurize the truth atlas -> sampling/truth sidecar
methscope upscale-featurize --embed-truth \
  atlas.cg panel.mrmp train.msur

# 2. group CpGs into processing units
methscope upscale-set-units --unit-cpgs 16384 \
  panel.mrmp units.msui

# 3. train (CUDA); --split pins the exact held-out cells,
#    else cells are cut 70/15/15 by --seed
make CUDA=1 CUDA_HOME=/path/to/cuda CUDA_ARCH=sm_80
methscope upscale-train -i train.msur \
  --units units.msui --mrmp panel.mrmp \
  -o model.updecx --work-dir work/ \
  --split cells.tsv

# 4. impute a sparse methylome with the bundle
methscope upscale -o imputed.cg \
  model.updecx test/human_hg38_test.cg

bundle / unbundle — package a model

A bundle wraps an inner model + its MRMP (+ labels) into one self-describing file (.ubjx / .updecx / .refx) so it ships and runs stand-alone.

methscope bundle -m panel.cm -l labels.txt \
  model.ubj -o model.ubjx
methscope unbundle model.ubjx      # -> parts

Runnable examples — models from HuggingFace, fixtures from GitHub

A four-part smoke test on the shipped models. Each featurizes against the whole-genome human MRMP, so allow ~1–2 min per test. Have yame on PATH and the conda env that provided libxgboost active.

# scratch dir; models from HuggingFace, .cg fixtures from methscope_data
mkdir -p ~/tmp/methscope-test && cd ~/tmp/methscope-test
hf download zhou-lab/methscope hg38_celltype.ubjx    --local-dir . # 62-type classifier
hf download zhou-lab/methscope hg38_65celltypes.refx --local-dir . # 65-type deconv ref
hf download zhou-lab/methscope hg38_10k1.updecx      --local-dir . # block-10k1 decoder
MD=https://raw.githubusercontent.com/zhou-lab/methscope_data/main/test
wget -q $MD/human_hg38_celltypes.cg $MD/human_hg38_celltypes.cg.idx  # 4 typed cells
wget -q $MD/human_hg38_immune_mixture.cg                             # 70% macro / 30% mono
wget -q $MD/human_hg38_test.cg $MD/human_hg38_test.truth.cg          # upscale input + truth

1 — cell-type prediction (cross-atlas concordance)

methscope classify human_hg38_celltypes.cg hg38_celltype.ubjx
cell             prediction_label  confidence
Oligodendrocyte  ODC               0.9151   # oligodendrocyte
Pancreas-Beta    Beta              0.9307   # islet beta
Blood-NK         NK CD16           0.8127   # natural killer
Blood-Monocytes  Mono              0.8360   # monocyte
# Loyfer truth -> Zhou2025 label: 4/4 concordant

2 — deconvolution, self-identity

# build a per-cell .refx; each cell must deconvolve to itself
methscope deconv-build-ref -o self.refx \
  human_hg38_celltypes.cg hg38_celltype.ubjx
methscope deconv human_hg38_celltypes.cg self.refx
# Oligodendrocyte  Oligodendrocyte=100%
# Pancreas-Beta    Pancreas-Beta=100%   ... (each 100% itself)

3 — deconvolution of a whole-body mixture

# simulated 70% macrophage / 30% monocyte vs the 65-type ref
methscope deconv human_hg38_immune_mixture.cg \
  hg38_65celltypes.refx
# 1   Macrophage=70%  Mono=29%   (truth 70/30; other 63 types ~0)

4 — upscaling from ~0.1% coverage

methscope upscale -o recon.cg \
  hg38_10k1.updecx human_hg38_test.cg
# block-10k1 calls vs ground truth
paste <(yame rowsub -I 1_10000 recon.cg | yame unpack -a - | cut -f4) \
      <(yame rowsub -I 1_10000 human_hg38_test.truth.cg | yame unpack -a - | cut -f4) \
  | awk '$2!=2{t++;if($1==$2)c++} END{printf "%d/%d (%.1f%%)\n",c,t,100*c/t}'
# 9211/9794 (94.0%)   — 94% accurate from ~0.1% input
